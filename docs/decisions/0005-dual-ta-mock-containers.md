# ADR-0005：本行 TA 与外部 TA 各自独立 Mock 容器

- 状态：已接受
- 日期：2026-09-15

## 背景

交易路由（申购/赎回按产品属性路由至本行 TA 或外部 TA）是被主线一强依赖的核心边界。候选：进程内 Mock 类、独立 Mock 服务（两个容器）、单一 Mock 服务承载双角色。

## 决策

本行 TA 与外部 TA 分别实现为 docker-compose 中两个独立 Mock 容器，通过 HTTP 与主系统交互。

## 理由

- 差错矩阵要求可演示"外部 TA 通信异常、结果未知、重复回调"——只有真实 HTTP 边界才能注入超时/重放/延迟确认
- 功能 27 要求展示路由链路，独立服务的调用在日志与链路追踪中可读
- 外部 TA Mock 需要可配置的故障注入开关（正常/超时/拒绝/延迟确认），作为评审演示的差异点
- 本行 TA 与外部 TA 行为模式不同（本行同步确认为主，外部异步确认+回调），分容器避免逻辑纠缠

## 后果

- docker-compose 服务数 +2，联调环境搭建成本略增
- 主系统与 TA 之间必须定义清晰的接口契约与报文流水号规范
