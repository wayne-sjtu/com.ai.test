# ADR-0003：C 端客户与管理端用户采用两套独立身份体系

- 状态：已接受
- 日期：2026-09-15

## 背景

理财产品销售平台（黑客松命题）同时服务 C 端客户（自然人投资者）与银行内部管理端用户（运营/客服）。需要决定身份模型是一张统一用户表加角色字段，还是两套独立实体。

## 决策

采用两套独立身份体系：`customer`（客户聚合）与 `operator`（管理端用户聚合），各自独立的登录入口、认证与 JWT claim。

## 理由

- 领域差异大：客户挂实名/尽调/风险测评/理财账户/持仓等概念，管理端用户挂组织/角色/数据权限，字段几乎无交集
- 命题主线二功能 50 明确要求"自营与代销岗位分开授权并拦截越权访问"，权限体系从管理端独立建模更自然
- 统一 user 表 + role 字段会让客户表塞满空的管理字段，且两套生命周期（客户注册流 vs 员工开通流）纠缠

## 后果

- 两套登录端点与两套 token 校验逻辑（claim 中区分 userType）
- 客户与管理端各自的会话管理、密码策略独立演化
